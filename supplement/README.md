# Supplement analyses

These are the scripts behind the supplement analyses that `reproduce.sh` does not run. They cover the further analyses of the duplication study (Supplementary Section S7) and the further analyses of the hidden-subtype study with Figure S5 (Supplementary Section S17). Each file is a copy of a script we ran. Only comments, docstrings and path defaults were edited (paths now read `HR_WORK`, `SUPP_DATA`, `GF_ROOT`), with defaults that resolve to the original paths, except that `further/embeddings/gfcfg.py` reads the cell list from `GF_CELLS_CSV`, which has no default because the original was a temporary file that was not released. One non-ASCII string literal in `figures/figS_further.py` was also written as an escape. The code is otherwise unchanged. Most produced printed numbers. The rest are the helpers, queues and checks they need. For the S7 paragraph on HLCA, `duplication/hlca_classifier_readout.py` (`run`, then `report`) scored the generated cells. The scripts that generated them are not here.

The scripts do not run from this repository alone. Paths inside them default to folders under `~/work` and `~/data` on our machines and the external volume `/Volumes/Files`; set `HR_WORK` to move `~/work`, `SUPP_DATA` to move `~/data` and `GF_ROOT` to move `~/geneformer/Geneformer`. `SUPP_DATA` is unrelated to the `HR_DATA` of the main pipeline. Some scripts also call `$HOME/venv` interpreters. Most read inputs that we did not release: the AIDA, HLCA and lupus files, the generated cells and the subsamples of the 10-atlas set. Read them as a record of what we ran. Script files carry plain descriptive names (`git log --follow` shows the earlier file names). Saved outputs, step keys, output folders, stored tables and the locked input tree still use our working codes, for example `m1_leiden_sub` (Leiden subclustering), `m14p` and `learn14_predict` (the learned scorer), `frozen4` and `preds_frozen4` (our method), `m27*`, `mk16`, `stat16*`, `rep16*` and `gen16*` output names (the donor-disjoint duplication runs), `w2_fm_*` (embedding-analysis output folders), `w6*` (label-corruption outputs), `r5` and `test5` (the test-atlas work folder and split name), and `sr3` (candidate-group outputs). The scripts load their locked inputs from the original working tree (`$HR_WORK/r5/code`), where the shared modules keep their earlier file names, so a rerun there needs those modules linked under the new names. Path defaults and comments also name folders of the original working tree: `jiaqi1011`, `j1004`, `rev1015`, `monday_q`, `recomb27`, `cfgen_natrare`, `w1`, `jiaqi1016`, `E2_major_types`, `opus_check` (under `tmp/`), `figaudit`, `hvg1015`, `hvg_c3`, `donorfix`, `src_mini`, `from_mini`, `p1data`, `si_v3`, `vm3_m12`, `r4_out`, `v4_integ`, `w6_annot_atac`, `scale_data`, `aida_sg`, `ablation_donor`, `gf6l_emb`, `recomb2027-r8i3wt`, `recomb2027-assets`, `preds_r2` and `preds_r2c` (method predictions and their combinations), `pcaspace_bak` (backups, with `preclip`, `preclip_stat16` and `<D>_sdiff_unclipped` holding outputs from before clipping), and the files `selection_amend2.txt` and `cand_api.json`; the defaults still point to them under `HR_WORK`. `mkh` is the marker and halo feature set of `learned_scorer`, `P4_s1` is the `learned_scorer` scoring rule the shipped scorer uses, and E1 or `E1_union` is the matched-k precision on the union of hidden cells (defined in `score_atl.py`). `scgpt_if` is the scGPT-embedding isolation-forest detector of the published-tool comparison. Comments and the run chains also name working scripts that are not included: `cfgen_aug.py` and `cfgen_knn.py` (our first CFGen augmentation and its kNN readout), `m27_gen_hlca.py`, `m27_gen_hlca_t.py` and `m27_gen_lupus_t.py` (the HLCA and lupus generator scripts), `m27_step1.py`, `m27_sd3clf.py`, `m27_mk.py`, `m27_hardmk.py` and `m27_repl.py` (earlier m27 classifier, marker and replicate readouts), `hl_counts.py` (the HLCA count rebuild), `sd3_arm_nofloor.R` (a copy of `sd3_arm.R` without the floor guard), `run_fm_dup_gf316m.py`, `01_shard_tokenize.py` and `02_embed.py` (our earlier Geneformer embedding scripts), `build_hlca.py` and `p3_pools.py` (earlier pool builders), `evaluate.py` (the evaluation step of `hmod`), `p1_planted_check.py` (a planted-label check), `make_paper_figs.py` and `plot_w1.py` (earlier figure scripts), and `mini_queue.sh`, `worker_sr3*.sh` and `timed.py` (the run queue, its workers and its timing wrapper). `BC1` to `BC4` and `check N` in `build_second_atlas_set.py` are its build-check status keys, and `leak5` and `build5` are its leak-check and build-status output folders. Other working labels in comments: set A = the 8-atlas test set (69 pools, `ablation_donor/data`); set B = the 10-atlas test set (57 pools, `r5/data`, split `test5`); phase-1 pools = the 29 set-B pools with pool index < 3; P1 to P3 are the parts of the label-corruption analysis; ASI, step0b and `step0b_ht` are our earlier scDesign3 augmentation pipeline (a separate project); "the mini" and "the laptop" are the two local machines we ran on, and a rented cloud GPU machine embedded the scGPT cells; `rank_combination_sweep` and test4/`r4` are earlier round names.

## Shared code

- `duplication/` holds the helpers that the scripts import: `statistical_arms.py` (classifiers and matched recall), `polh.py` (the sign-flip test), `sdiff_mod.py` (our scDiffusion wrapper), `hlca_classifier_readout.py` (classifiers for AIDA, HLCA and lupus), `metrics/common.py` (data loading for `run_e1.py`) and `mem_patch.R` (a memory patch for scDesign3). `dup_vs_generators_rawcounts.py` writes the saved cells of the eight usual types that later scripts read.
- `further/method_at_submission/` is our method as it stood when we ran the further analyses, which import it. `hiddenrare/` at the repository root is the released version.
- `further/embeddings/`, `further/labels_and_atac/` and `further/scale_and_regressors/` also hold shared helpers: `harness.py`, `embedding_lib.py`, `label_corruption_common.py`, `gfcfg.py` and `gfload.py` (Geneformer loading for `embed.py`), `common.sh` (sourced by the w2 queues), `laptop_lock_run.sh` (a lock wrapper that `fm_queue_gf.sh` and `fm_plumbing_check.sh` run) and the pool lists.
- `further/queues/` holds the shell scripts that ran the jobs in order.

We did not copy third-party code. CFGen, scDiffusion and Geneformer load from clones of the authors' repositories. scGPT and scvi-tools come from pip, and scDesign3 and snapATAC2 are installed packages.
